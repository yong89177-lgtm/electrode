# MAPS · 생산기술혁신센터 AI 플랫폼 — 백엔드 배포 가이드

> 이 저장소는 [yong89177-lgtm/MAPS](https://github.com/yong89177-lgtm/MAPS)의 `deploy/index.html`을 이 저장소에서
> 자유롭게 수정할 수 있도록 그대로 가져온 버전입니다. `deploy/index.html`의 CSS에는 여러 차례의 전면
> 리디자인(V10 → V11 → V13 → 현재 히어로 개편)이 겹겹이 쌓여 있었는데, 실제 마크업에서 더 이상 쓰이지
> 않는 이전 버전의 CSS 규칙(약 140개 선택자 · 12.6KB)을 정적 분석으로 찾아 제거해 화면은 동일하게 유지하면서
> 파일 용량만 가볍게 만들었습니다.

`deploy/index.html`(프런트엔드)이 기대하는 `api/*` 백엔드를 **Vercel Serverless Functions + Vercel Blob**
으로 구현했습니다. 로그인/회원가입, 대시보드 등록요청 2단계 승인, 게시판·라운지·자료공유, 팝업·매뉴얼,
그리고 관리자 콘솔의 "HTML 업데이트"(포털 화면 자체 교체)까지 전부 동작합니다.

## 배포 절차 (최초 1회)

1. 이 저장소를 Vercel 프로젝트로 Import 합니다. (Framework Preset: **Other** 로 두면 됩니다 — 빌드 명령 없음)
2. Vercel 프로젝트 → **Storage** 탭 → **Create Database** → **Blob** 을 눌러 Blob Store 하나를 연결합니다.
   연결하면 `BLOB_READ_WRITE_TOKEN` 환경변수가 자동으로 추가됩니다.
3. **Settings → Environment Variables** 에 아래 값을 추가합니다.

   | 변수 | 값 | 설명 |
   |---|---|---|
   | `ADMIN_PASSWORD` | 원하는 초기 관리자 비밀번호 | 필수. 최초 배포 시 이 값으로 `admin` 계정이 자동 생성됩니다. |
   | `ADMIN_ID` | (선택, 기본값 `admin`) | 최초 관리자 아이디를 바꾸고 싶을 때만 설정 |
   | `BLOB_PATH_SECRET` | 32자 이상의 임의 문자열 | 필수. 데이터 저장 경로의 접두어로 써서, Blob이 "공개" 접근이어도 URL을 모르면 못 읽게 합니다. 아래 명령으로 생성하세요. |

   ```bash
   openssl rand -hex 32
   ```

   `BLOB_PATH_SECRET` 은 한 번 정하면 절대 바꾸지 마세요 — 바꾸면 기존에 저장된 모든 데이터(계정, 게시글 등)를 찾지 못합니다.

4. **Deploy**. 배포가 끝나면 사이트에 접속해 관리자 로그인(설정 톱니바퀴) → 위에서 설정한 `ADMIN_ID`/`ADMIN_PASSWORD` 로 로그인합니다.
5. 로그인 후 관리자 콘솔 → 계정 관리에서 `admin` 비밀번호를 다시 한번 원하는 값으로 바꿔두는 것을 권장합니다
   (환경변수의 `ADMIN_PASSWORD`는 계정이 이미 만들어진 뒤에는 더 이상 참조되지 않습니다).

이후 회원가입은 "승인 대기" 탭에서 관리자가 승인해야 로그인할 수 있습니다.

## 사내망 PC/서버에서 직접 실행하기 (Vercel 없이)

`http://10.31.52.153:8081` 처럼 사내망 IP로 띄우고 싶다면, Vercel도 Blob도 필요 없습니다 —
그 서버에 이 저장소를 내려받아 Node.js로 바로 실행하면 됩니다. 데이터는 그 PC의 로컬 디스크
(`data/` 폴더)에 저장됩니다.

1. 그 PC/서버에 [Node.js 18 이상](https://nodejs.org)을 설치합니다.
2. 이 저장소를 내려받습니다 — GitHub 페이지의 초록색 **Code → Download ZIP** 버튼으로 받아서 압축을
   풀거나, `git clone https://github.com/yong89177-lgtm/MAPS.git`.
3. 압축 푼(또는 clone한) 폴더 안의 실행 스크립트를 더블클릭합니다.
   - Windows: **`start-maps.bat`**
   - Mac/Linux: **`start-maps.sh`** (터미널에서 `./start-maps.sh`로 실행하거나, Mac에서는
     더블클릭 후 "터미널에서 열기"를 선택)

   이 스크립트가 패키지 설치(사내망 보안 프로그램 때문에 흔히 나는 `SELF_SIGNED_CERT_IN_CHAIN`
   인증서 오류도 자동으로 우회합니다), `.env` 파일 생성(최초 실행 시 관리자 비밀번호를 기본값
   `maps1234`로 자동 설정), 서버 실행까지 전부 알아서 처리합니다. 콘솔 창에
   **"MAPS 서버 실행 중 — http://이 PC의 사내망 IP:8081"** 이 뜨면 성공입니다.
4. 로그인(아이디 `admin`, 비밀번호 `maps1234`) 후 관리자 콘솔 → 계정 관리에서 비밀번호를 바로
   바꿔두세요. (미리 원하는 비밀번호를 쓰고 싶다면, 실행 전에 `.env.example`을 복사해 `.env`로
   저장하고 `ADMIN_PASSWORD` 값을 직접 채운 뒤 스크립트를 실행하면 됩니다.)
5. 같은 사내망에 있는 다른 PC에서 `http://<이 서버의 IP>:8081` 로 접속하면 됩니다 (그 PC의 방화벽에서
   8081 포트를 열어줘야 할 수 있습니다). 이 PC의 IP는 명령창에서 `ipconfig`(Windows) /
   `ifconfig`(Mac)로 확인합니다.
6. 스크립트를 실행한 창을 닫으면 서버도 꺼집니다. 컴퓨터를 재부팅해도 계속 떠 있게 하려면
   [pm2](https://pm2.keymetrics.io/) 같은 프로세스 매니저나 Windows 서비스 등록 도구로 등록해두는
   걸 권장합니다 (`pm2 start standalone.js --name maps`).

이 방식과 Vercel 배포는 **같은 코드베이스를 그대로 씁니다** — 서버 라우트 코드(`server/*.js`)는 동일하고,
저장소 구현만 실행 환경에 따라 자동으로 바뀝니다 (`server/_lib/blob.js` 참고). 둘 중 하나만 선택해도 되고,
필요하면 둘 다(Vercel은 외부 접속용, 사내 서버는 내부 접속용) 동시에 운영해도 됩니다 — 다만 데이터는
서로 공유되지 않고 각자 따로 저장됩니다.

## 아키텍처 요약

- **데이터 저장**: 계정/게시글/댓글/라운지/자료공유/대시보드 상태/승인이력 등 모든 JSON 데이터와, 첨부파일·이미지·HTML 업로드 같은 바이너리를 전부 한 곳에 저장합니다 — Vercel에서는 **Vercel Blob**(`server/_lib/blob-vercel.js`), 사내망 독립 실행에서는 **로컬 디스크**(`server/_lib/blob-local.js`)를 씁니다. `server/_lib/blob.js`가 `process.env.VERCEL` 유무로 둘 중 하나를 자동으로 골라주기 때문에 라우트 코드는 신경 쓸 필요가 없습니다. 브라우저에는 저장소의 실제 위치를 절대 노출하지 않고, 항상 `/api/*` 라우트가 서버에서 대신 읽어 스트리밍합니다.
- **세션/로그인**: 비밀번호는 `scrypt` 로 해시해 저장합니다. 로그인하면 서버가 무작위 세션 토큰을 발급해 Blob에 저장하고, 브라우저에는 `HttpOnly` 쿠키로만 토큰을 내려줍니다(JWT 아님 — 로그아웃 시 서버에서 즉시 폐기됩니다).
- **`data/dashboards.json`**: 원래 정적 파일이었던 이 경로를 `vercel.json` 리라이트로 `/api/dashboards-data` 함수에 연결해, 관리자 콘솔에서 저장한 대시보드 배치가 실제로 반영되도록 했습니다.
- **"HTML 업데이트" (포털 전체 교체)**: 원래 구조는 정적 파일 배포라 관리자가 새 HTML을 올려도 실제로 반영될 방법이 없었습니다. 이를 위해 **루트(`/`) 요청 자체를 `server/render.js`가 동적으로 응답**하도록 바꿨습니다 — 저장소에 저장된 최신 HTML이 있으면 그것을, 없으면(최초 배포 시) 저장소에 포함된 `deploy/index.html`을 내려줍니다. 관리자가 업로드하면 이전 버전은 다운로드 가능한 이력으로 보관됩니다.
- **히어로 배경 동영상**: 원래 `deploy/index.html` 안에 base64로 통째로 박혀 있어 파일이 20MB였습니다. Vercel 서버리스 함수는 응답 4.5MB 제한이 있어 이 상태로는 render 함수가 절대 응답할 수 없었기 때문에, 영상을 `hero-bg.mp4` 라는 별도 정적 파일로 분리하고 HTML에서는 그 경로만 참조하도록 고쳤습니다 (`deploy/index.html`은 이제 약 350KB).
- **함수 개수**: 라우트가 60개가 넘어서 파일마다 하나씩 `api/*.js`로 두면 Vercel Hobby(무료) 플랜의 "배포당 서버리스 함수 12개" 제한을 훌쩍 넘습니다. 그래서 실제 라우트 구현은 전부 `server/*.js`에 두고, 배포되는 서버리스 함수는 `api/[...slug].js` **하나**뿐입니다 — 요청이 오면 URL의 마지막 조각(`/api/login` → `login`)을 보고 내부에서 알맞은 `server/*.js` 파일로 분기합니다.

## 알려진 제약사항 (설계상 트레이드오프)

- **첨부파일 업로드 용량 (Vercel 배포에서만 해당)**: 게시판/라운지/자료공유 화면은 "최대 100MB" 라고 안내하지만, 이 백엔드는 파일을 base64로 감싸 JSON 요청 본문으로 보내고, **Vercel 서버리스 함수는 요청 본문 자체가 4.5MB로 제한**되어 있습니다. Vercel에서는 실제로 파일당 대략 3MB 안팎까지만 올라갑니다. 진짜 100MB를 지원하려면 브라우저가 Blob에 직접 업로드하는 방식(Vercel Blob Client Upload)으로 프런트엔드까지 고쳐야 하는데, 이번 작업 범위에는 포함하지 않았습니다. **사내망 독립 실행형 서버(`standalone.js`)에는 이 제한이 없습니다** — 안내대로 100MB까지 그대로 올라갑니다.
- **관리자 "HTML 업데이트"도 같은 이유로 4MB 제한**을 걸어뒀습니다. 큰 이미지/동영상은 문서에 base64로 넣지 말고 별도 파일이나 외부 링크로 참조하세요.
- **대시보드 타일 "장애/정상" 상태**: 사내망 전용 IP·주소는 Vercel(퍼블릭 클라우드)에서 접속성을 확인할 수 없어, 자동 헬스체크는 하지 않습니다. 관리자가 수동으로 걸어두는 "유예" 토글만 동작합니다.
- **읽기 지연 가능성**: 데이터를 바꾼 직후(다른 서버리스 인스턴스가 처리하는) 다음 요청에서 아주 짧은 시간(수 초) 동안 이전 값이 보일 수 있습니다(Blob 엣지 캐시 특성). 사내 소규모 포털 트래픽에서는 문제되지 않는 수준입니다.
- **대시보드 등록요청 승인 후 자동 배치는 하지 않습니다**: 2차 승인이 끝나면 상태가 "반영 완료"로 바뀌지만, 실제로 그리드에 타일을 추가하는 건 여전히 관리자가 "대시보드 관리" 탭에서 직접 해야 합니다.

## 원래 겪고 있던 문제와의 관계

"AI Agent 등록요청" 에서 HTML을 넣고 제출하면 "서버에 연결할 수 없습니다"가 뜨던 것은, `api/dash-request` 를
처리할 백엔드가 저장소에 아예 없었기 때문입니다(`api/*` 47종 전부 없었습니다). 이번 작업으로 그 요청을
포함한 전체 기능이 실제로 저장·조회·승인되도록 구현했습니다. 위 배포 절차대로 Vercel에 Blob을 연결하고
환경변수를 설정해야 실제로 작동합니다 — 코드만으로는 저장할 곳이 없어 여전히 실패합니다.
